Build your first application

A hands-on tutorial using the actual multiplication scaffold. By the end you will inspect, execute, deliberately break and restore a contract.

On this page1. Scaffold outside the framework2. Read the three definitions3. Validate and run4. Explore the behavior5. Prove that execution is not fulfillment6. Add a regression fixture7. Move beyond multiplication

1. Scaffold outside the framework

Complete the installation guide, then run in a directory where you keep projects.

gh ic3o init my-app
cd my-app
gh ic3o inspect pep/my-app.pep
my-app/
  context/my-app.context
  contract/my-app.contract
  pep/my-app.pep
  fixtures.json
  README.md
  .gitignore

The generated app is a multiplication starter, not a complete business application. The command refuses to overwrite an existing project directory.

2. Read the three definitions

Context: context/my-app.context

Order context
Fields
    quantity: Quantity
    price: Unit price
    total: Total price

Contract: contract/my-app.contract

Order contract
Require
    quantity >= 0
    price >= 0
Guarantee
    total = quantity * price

PEP: pep/my-app.pep

my-app
Intake
    quantity: integer
    price: integer
Capability
    total = multiply.capability(quantity, price)
Outtake
    total: integer
    total -> response

The matching stems bind Context and Contract implicitly. multiply.capability is already available from the registry.

3. Validate and run

gh ic3o validate pep/my-app.pep
gh ic3o resolve pep/my-app.pep
gh ic3o test pep/my-app.pep
gh ic3o run pep/my-app.pep quantity=7 price=13

Expect two passing scaffold fixtures, then output total: 91. The trace lists requirements, the actual capability input and output, and the guarantee. Resolve reports existing bindings; it does not choose an implementation for you.

4. Explore the behavior

This small browser exercise models the starter's integer inputs and contract. It is an educational simulation, not the actual runtime. The CLI remains the authoritative execution path.

Select Evaluate example.

5. Prove that execution is not fulfillment

Run a rejected input:

gh ic3o run pep/my-app.pep quantity=-1 price=5

Now open contract/my-app.contract in your editor. Temporarily replace its guarantee with total = quantity + price. Re-run the input 7 and 13. Expect a guarantee failure, despite multiplication producing 91. Restore total = quantity * price and rerun the tests.

Use a single arithmetic operation. The current assertion evaluator does not support expressions such as quantity * price + 1.

6. Add a regression fixture

Open fixtures.json and append this object to the existing JSON array, separating it from the previous object with a comma.

{
  "name": "zero quantity",
  "input": {"quantity": 0, "price": 5},
  "expected": {"total": 0}
}

Run gh ic3o test pep/my-app.pep again. Expect three passing cases. This extends evidence for the application without changing the contract.

7. Move beyond multiplication

Browse the bundled order and Mode-backed examples through gh ic3o dashboard → Applications → Browse bundled examples. Those demonstrate child PEPs and reusable infrastructure. The composition guide explains how they work.
