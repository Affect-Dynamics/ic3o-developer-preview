Five responsibilities, four native file types

ResponsibilityQuestionWhere it lives
IntakeWhat enters this network?PEP
ContextWhat does this information mean?.context
ContractWhat must be true before and after execution?.contract
CapabilityWhat fulfills the operation?.capability or another PEP
OuttakeWhat leaves, and where is it addressed?PEP

PEP is the executable composition. Context and Contract may be referenced explicitly or resolved by convention. The preview's Context fields describe semantics; they do not automatically fetch state.

Follow one order

A customer requests 12 units, only 8 are available, and the unit price is 5. A bounded allocation network returns 8. Its parent multiplies that by the price and subtracts it from inventory available. The resulting total is 40 and remaining is 0.

Contracts are not fixtures

A fixture checks a particular scenario. A contract applies on every ordinary execution. Requirements reject unacceptable inputs; guarantees reject outputs that fail the declared obligation, even if the implementation completed successfully.

Order contract
Require
    quantity >= 0
    price >= 0
Guarantee
    total = quantity * price

For example, a negative quantity fails before multiplication. A mismatched total fails the guarantee. This is executable checking, not a formal proof of all possible program behavior.

Routes are not external effects

Outtake contains typed output declarations and routes. The preview returns delivery envelopes such as response and inventory_preview. A route alone does not update an external inventory system.

Framework versus engine

ic3o can run on ThICCC, which adds probabilistic routing. The public developer preview resolves existing bindings deterministically. It neither discovers a missing implementation automatically nor requires an AI service. gh-ic3o is the contributor interface, not ThICCC.
