Attach a sidechain

Use
    provenance
Sidechain
    provenance:provenance.pep

A sidechain is an ordinary PEP attached to a scope. Ancestor attachments are inherited by descendants. A child attachment does not activate on its parent. Hooks are synchronous and mandatory in the preview.

PhaseWhen
intakeNetwork intake
before_executeAfter requirements
after_executeAfter guarantees
before_outtakeBefore successful return
failureWhen an error propagates

The interface takes text inputs phase, path and digest. Hooks apply at PEP boundaries, not every native operation. A hook failure prevents successful Outtake. The order sidechain example produces eight successful lifecycle events across two network levels.

Trace versus journal

Ordinary execution returns trace entries, including sidechain commitments. Durable execution journaling requires the explicit journal wrapper. It can record rejected attempts. Hash commitments and chains are not independently authenticated, do not hide low-entropy inputs, and require a trusted checkpoint for meaningful verification. Do not put secrets in traces.

Network-scoped frontends

The bundled order project exposes frontend paths for root and root/allocation. Inspect them with gh ic3o frontends, or pass a project path. In a framework checkout, npm start serves the local example on loopback, normally port 8799. It is unauthenticated and must not be exposed to untrusted networks.

Persistence preview

The persisted-note reference uses a trusted host to bind one entity scope, a synchronous write policy and tracked SQLite storage. Data, field revisions and successful evidence commit together. A failed guarantee, write, policy or evidence insertion rolls back the transaction. This does not make ordinary PEP runs transactional automatically.

node projects/persisted-note/demo.mjs
node projects/persisted-note/demo.mjs ./notes.db

Run from a framework checkout. The reference is insert-only, not a general persistence provider; its policy is intentionally permissive for synthetic data. Rejected attempts are not durably journaled by this transaction wrapper.

Trust boundaries

Trusted local definitions, no untrusted plugin isolation, no production authentication, no general external side-effect rollback and no independently anchored evidence. Do not use this preview as a production security boundary.
