Native definition reference

A practical reference for the current preview grammar, not a promise of a stable language specification.

On this pageGeneral syntaxPEPContextContractCapabilityReference resolutionFixtures and validation

General syntax

The first nonempty line is a title. Sections are case-sensitive and entries are indented. Comments begin with #. Dependencies must appear before consumers.

TypeMeaning
integerSafe integer
numberFinite number
textString
booleanBoolean

PEP

my-app
Intake
    quantity: integer
    price: integer
Capability
    total = multiply.capability(quantity, price)
Outtake
    total: integer
    total -> response

Intake declares inputs. Capability assigns results of named invocations. Outtake declares typed outputs and their destinations. The optional source: POST /api/run used in bundled examples describes entry metadata. An individual call currently binds one output.

Context

Order context
Fields
    quantity: Quantity
    price: Unit price
    total: Total price

Fields describe meaning. Reference more than one Context when a network shares semantics with another network.

Contract

Order contract
Require
    quantity >= 0
    price >= 0
Guarantee
    total = quantity * price

Requirements run before capability execution and guarantees before returning results. Supported comparisons: = != >= <= > <. Operands can include named variables, numeric literals, one arithmetic operation or min(a, b). This is a limited assertion evaluator, not JavaScript or a general expression language.

Capability

Native capability files declare typed Intake and Outtake and an Implementation section using native: name. The implementation name must exist in the runtime allowlist. Adding arbitrary JavaScript or a new native name to a definition does not make it executable. Inspect the real multiply definition ↗ as an example. For new reusable functionality prefer composition of supported operations; propose new core primitives through review.

Reference resolution

ReferenceMeaning
allocation.pepLocal sibling PEP, then visible Modes
../rules/order.contractExplicit path relative to the referring PEP
commerce:order.contractQualified asset in a visible Mode
Omitted Context or ContractMatching stem in sibling directory, with supported Mode fallback

Explicit Context and Contract sections replace default lookup for that section. List the default explicitly if you want to keep it alongside extra references. Missing defaults and empty explicit sections fail; they do not bypass enforcement. Absolute paths inside native declarations are not supported.

Fixtures and validation

Fixtures contain a name, input, and expected output or expected error. Structural validation checks references, types, dependencies and routes, not mathematical equivalence or every assertion expression. Execute fixtures and additional inputs to test runtime behavior.
