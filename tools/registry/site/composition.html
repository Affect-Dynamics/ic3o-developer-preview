Networks and Modes

Use the same interface to invoke a primitive operation or an entire network. Then package reusable definitions as Modes.

A capability can be a network

Capability
    allocation = allocation.pep(requested, available)
    total = multiply.capability(allocation, unit_price)
    remaining = subtract.capability(available, allocation)

The allocation PEP has its own Intake, Context, Contract and Outtake. The parent consumes its returned allocation, while its internal contract remains active. Trace paths preserve the calling hierarchy.

Bounded allocation
Intake
    requested: integer
    available: integer
Context
    order.context
    allocation.context
Capability
    allocation = minimum.capability(requested, available)
Outtake
    allocation: integer
    allocation -> parent

Import a Mode

A Mode is a local reusable library of the four native definition types, not a new native primitive. It may also provide frontend assets. Commerce declares its numerical dependency in mode.json.

Use
    commerce

Context
    commerce:order.context

Contract
    commerce:order.contract

Capability
    allocation = allocation.pep(requested, available)
    total = numerical:multiply.capability(allocation, unit_price)
    remaining = subtract.capability(available, allocation)
mode/commerce/mode.json
{"use":["numerical"]}

The qualified numerical reference is visible transitively because commerce depends on numerical.

Deterministic resolution order

  1. Resolve an explicit relative path or qualified visible Mode reference.
  2. For a bare reference, check the conventional local directory.
  3. Search visible Modes and their dependencies. Reject ambiguous matches instead of choosing by import order.
  4. For a capability only, fall back to the universal registry.
  5. Reject unresolved references.

A local child inherits caller-visible Modes and may import more. A Mode-owned child resolves within its own Mode dependency scope, plus explicit imports. Static reference and Mode dependency cycles are rejected.

Try the bundled example

gh ic3o modes
gh ic3o dashboard

Register the bundled mode-order example in Applications. Alternatively, from a trusted framework checkout:

node cli.mjs inspect projects/mode-order
node cli.mjs test projects/mode-order
node cli.mjs run projects/mode-order requested=12 available=8 unit_price=5

Expect allocation 8, total 40 and remaining 0. The same outcome is available in the local order example. The trace reveals the resolved origins, not merely the final number.

Package work for reuse

Separate domain-specific definitions into a focused Mode, include dependencies, document inputs and guarantees, add a reference project and fixtures, and submit a reviewed PR. Independent remote Mode installation and version locks are not available yet.
