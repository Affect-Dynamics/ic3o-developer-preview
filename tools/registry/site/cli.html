gh-ic3o command reference

The contributor extension wraps a verified local framework snapshot. Use it from your application or contribution checkout.

On this pageEnvironment and revisionsApplication commandsRegistry and GitHub commandsDashboard workflowWhat sync actually does

Environment and revisions

CommandPurpose
gh extension upgrade ic3oUpdate the extension itself
gh ic3o loginOfficial GitHub CLI web authentication
gh ic3o whoamiShow GitHub identity
gh ic3o checkFetch upstream revision without activation
gh ic3o syncFetch and test a candidate; activate if verified
gh ic3o statusDisplay active and previous revisions
gh ic3o rollbackSwitch to previous installed revision; does not undo app data
gh ic3o dashboardOpen contributor interface (also the default command)

Application commands

Command after gh ic3oPurpose
init NAMECreate a starter in the current directory
inspect FILEDisplay resolved network tree
validate FILECheck structural bindings
resolve FILEReport existing bindings; no automatic discovery
run FILE key=valueExecute with explicit inputs
test FILE [FIXTURES]Execute fixtures; optional custom fixture file
modesList local Modes and dependencies
frontends FILEList frontend paths and actions

FILE can be an entry PEP or conventional project directory. Use explicit paths when working with custom layouts. Some supported commands are not listed in the extension's short help at this revision.

Dashboard workflow

Use Applications to scaffold, register an existing local PEP, clone a GitHub repository, or browse bundled examples. Registered apps can be inspected, tested, run or unregistered without deleting their files. The dashboard registry browser includes Mode artifacts, unlike the current flat registry search command. Review the displayed source and attribution when selecting a definition.

What sync actually does

Framework, registry and Modes are pinned together under ~/.ic3o/preview. Sync fetches a trusted upstream Git revision, checks snapshot integrity, runs tests for new revisions, then atomically updates the active pointer. Application files are kept separate. The launcher rejects modified snapshots. Do not edit them; clone the framework for contributions.

Sync executes upstream test code. Commit identity and passing tests are not publisher signatures or sandbox isolation. Do not redirect the updater to unknown forks. No background update, automatic disk pruning or app-specific lockfile.
